# FerresDB — Project Overview

## Name
`ferres-db` (crate: `ferres-db-core`, binary: `ferres-db-server`)

## What it does
High-performance vector search engine written in Rust. Designed for semantic search, RAG (Retrieval-Augmented Generation) pipelines, and recommendation systems. Provides:
- HNSW-based ANN vector search with Cosine, Euclidean, and Dot Product metrics
- Hybrid search (vector + BM25 keyword, fused via RRF or weighted scoring)
- Disk persistence with WAL, periodic snapshots, and crash recovery
- Multi-tenancy via logical namespaces
- REST API (Axum), optional gRPC (tonic), and MCP (embedded STDIO server)
- React/TypeScript dashboard for collection management, analytics, graph exploration
- Python and TypeScript SDKs

## Stack
| Layer | Technology |
|---|---|
| Core engine | Rust 2021, `hnsw_rs`, `rayon`, `memmap2`, `zstd` |
| HTTP server | Axum 0.8, Tower, `tokio` async runtime |
| gRPC (optional) | `tonic 0.12`, `prost 0.13` |
| MCP (optional) | `rmcp 0.14` |
| Persistence | JSON-lines + WAL + bincode snapshots, SQLite (users/keys) |
| Quantization | SQ8 (Scalar Quantization), PolarQuant, QJL residual correction |
| Auth | Argon2 + JWT, API keys (SQLite), RBAC with audit trail |
| Metrics | Prometheus (`prometheus` crate), OpenTelemetry (optional `otel` feature) |
| S3 backup | `aws-sdk-s3 1`, `tar`, `flate2` |
| Dashboard | React 19, Vite 7, TypeScript, Tailwind CSS, TanStack Query |
| Python SDK | `httpx`, `structlog`, `websockets` (Python ≥ 3.8) |
| TypeScript SDK | `tsup`, `vitest` |
